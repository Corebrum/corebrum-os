Zenoh

Zenoh · zenoh.io

ROS 2 on Corebrum talks through one Zenoh router. That router listens on port 7447. Shells on this machine are clients of it and connect to tcp/localhost:7447. Corebrum runs that router as corebrum-zenoh-router.service. Leave it as the only router. ros2 run rmw_zenoh_cpp rmw_zenohd would take the same port.

After ROS 2 is installed, Super+Space lists Zenoh network. Choosing it runs zenoh network and draws the nodes connected to the router.

Commands

corebrum zenoh status
corebrum zenoh peers
zenoh info
zenoh subscribe -k 'rt/**'

corebrum zenoh status shows the router unit and the listen address. corebrum zenoh peers shows that address and this machine’s IPv4 addresses. zenoh info opens a client session to the existing router. zenoh subscribe prints samples on a key expression.

A second machine

Install the same ROS profile on the other machine. On the machine whose router will carry the messages, run corebrum zenoh peers and choose an address. Point both shells at that router as Zenoh clients, on tcp/<router-address>:7447, and keep both on the same ROS_DOMAIN_ID. A publisher left on the default peer session listens on 127.0.0.1, which the other machine can see and cannot open.

Zenoh fleet

Zenoh fleet is a separate Super+Space row. It says install until zenoh-fleet is present. Choosing it installs @corebrum/zenoh-fleet 0.1.4 and runs the wizard. The wizard writes files in the home directory, under ~/local-fleet/ by default, and does not change the running router.
